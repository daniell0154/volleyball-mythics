# Aceite 013 — somente 2v2 online

## Reprodução

```powershell
npm run build
node docs/acceptance/013-fixture-server.mjs
# Outro terminal, na raiz:
node node_modules/vite/bin/vite.js --config apps/web/vite.config.ts --host 127.0.0.1 --port 5178
# Outro terminal:
node docs/acceptance/013-journey.cjs
node --test apps/server/tests/2v2-acceptance.test.mjs
node supabase/tests/database/005_match.cjs
```

Playwright em .test-build/browser e PGlite em .test-build/sql são dependências exclusivas dos harnesses. Servidor 3016 serve a build de produção e sockets; catálogo de fixture em 3017; apresentação de teste em http://127.0.0.1:5178/docs/acceptance/013-preview/. O harness reutiliza catálogo inicial e três entradas fictícias locais. Não publica dados nem modifica auth de produção.

A consulta da build real em /, /demo e /preview deve mostrar entrada 2v2, sem demonstração; /admin deve montar a administração. Sem .env, esses checks não autenticam no Supabase nem comprovam login remoto. O percurso de jogo usa Lobby/OnlineMatch reais com gateway guest de teste, transporte, runtime, resultados e lifecycle reais; persistência no fixture é sem banco.

Quatro contextos separados: convidar pelo código/link, escolher mesmo atleta, marcar pronto, verificar dono exclusivo e início, sacar por teclado, aguardar seis pontos por simulação real e votar na revanche. Três votos não bastam; quarto voto inicia novo matchId/placar zero. Abandonar a revanche encerra com placar real zero, sem fabricar seis pontos. Não é playtest humano de rally nem validação de equilíbrio do saque (spec 014).

Testes Node usam relógio controlado para cobrir suspensão/retomada, prazo de 20s, limite acumulado de 40s por equipe e ambos os lados incompletos. Integração de sockets cobre ainda lotação, pedido 1v1 rejeitado sem criar membership e visitante sem acesso a snapshots. A regressão SQL lê/persiste resultados históricos 1v1, idempotência, conflito e rollback sem estreitar o enum; nenhuma migration nova.

Relatório do navegador em 013-results.json; capturas 013-entry.png/013-lobby.png/013-match.png. Os scripts 011/012 documentam aceites anteriores e podem assumir criação 1v1; o percurso ativo de modos é o 013, com quatro humanos. Fixtures 1v1 internas de domínio/servidor permanecem para regressão histórica.

Limites: ambiente local Windows/Chrome, sem WAN, Supabase hospedado, Firefox/Safari ou benchmark de GPU novo. Entradas inválidas e erros de protocolo são registrados no relatório, incluindo invalid_state de inputs em transições de fase. Aprovação do proprietário necessária para fechar a experiência; 014 só começa depois de integrar 013.
